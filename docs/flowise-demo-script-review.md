# Flowise 攻防演练剧本全流程描述

## 0. 剧本定位

这个剧本描述的是一次多智能体协同攻防演练。

演练目标不是传统 CTF flag，而是业务化目标：

```text
目标已达成：夺取办公网最高权限
```

剧本从一个外网域名和公网入口开始，逐步推进到 AI 编排平台、后端执行能力、内网拓扑、核心资产定位、域控权限验证，最后以真实内网攻击阶段日志补全全域渗透过程。

基础信息：

- 目标名称：对 X 目标公司进行攻防演练
- 目标描述：获取目标办公网核心权限
- 起始入口：`target.com`、`203.0.113.41:443`
- 剧本来源：`flowise-demo-script`
- 参与智能体数量：6
- 首次启动：2026-06-13 02:45:00
- 最终提交：2026-06-13 06:23:00

```text
公开资产测绘

  -> 漏洞分析智能体
  -> 漏洞利用智能体
  -> 内网渗透智能体
  -> 域控接管智能体
```

各角色职责如下：

| 顺序 | 智能体 | 剧本角色 | 接收输入 | 交付输出 |

| 3 | 漏洞分析智能体 | 梳理漏洞机理 | Web 攻击面线索 | 未知风险线索、组合型高危利用链、验证条件 |

## 2. 第一阶段：从外网域名到 Flowise-like 入口

### 2.1 启动条件

剧本以客户给定的外网目标为起点：

```text
target.com
203.0.113.41:443
```

公开资产测绘智能体的初始任务是：不预设内网结构，仅基于公开信息建立外网攻击面。

它首先围绕以下维度建立查询条件：

- DNS 记录
- 证书主体
- 备案信息
- HTTP 标题
- 图标哈希
- 历史暴露记录

### 2.2 候选资产收敛

公开资产多条件检索返回 7 条候选外网资产。

智能体对候选资产做了排除和归并：

- 排除 CDN 边缘节点
- 排除历史下线服务
- 排除测试子域
- 按时间戳、证书主体、响应指纹去重

最终保留：

```text
203.0.113.41:443
```

该入口被识别为：

```text
Flowise-like AI workflow console
```

### 2.3 外网入口暴露能力

剧本中该 Flowise-like 平台暴露了多个后续可利用能力：

- 工作流编排
- 节点执行
- 凭据托管
- 工具市场
- Webhook 回调
- API key 管理

至此，第一阶段的输出不是“漏洞”，而是一个明确的攻击面模型：外网 AI 编排平台具备工作流、凭据、插件和连接器等组合能力。

## 3. 第二阶段：外网攻击面建模

### 3.1 应用渗透智能体接手

应用渗透智能体接收资产测绘输出的公网入口和攻击面模型，开始围绕 Flowise 类平台做 Web/API 验证。

它的验证范围包括：

- 管理控制台
- API schema
- 工作流导入
- 凭据管理
- 危险节点
- URL loader
- Webhook listener
- 前端 bundle

### 3.2 攻击面优先级排序

剧本将攻击面分成多个优先级：

```text
P0: prediction / internal-prediction 后端执行与节点运行
P1: credentials/:id/reveal 与 variables 凭据边界
P1: export-import/import 工作流导入
P2: public-chatflows / flow-config / chatmessage 白名单接口 IDOR
P2: document-store / fetch-links / webhook-listener URL 访问链
P3: 前端 bundle 信息泄露
```

这个排序决定后续验证顺序：先确认可稳定读取的信息和凭据引用，再推进后端执行、SSRF 和内网探测。

### 3.3 白名单接口 IDOR 线索

应用渗透智能体重点验证 Flowise 白名单接口和 Chatflow 资源引用。

涉及接口包括：

- `/api/v1/chatflows/apikey/:apikey`
- `/api/v1/public-chatflows/:id`
- `/api/v1/flow-config/:id`
- `/api/v1/chatmessage/:id`

剧本中的逻辑判断是：

如果这些接口只校验 ID 格式、白名单状态或 Chatflow 可用性，而没有绑定当前用户/租户归属，就可能越权读取以下信息：

- Chatflow 配置
- nodes / edges
- credentialId
- overrideConfig
- 变量引用
- 会话上下文
- 文件路径线索

### 3.4 凭据与错误回显线索

凭据模块被用于辅助定位后续利用路径。

剧本设定中，错误响应可能泄露：

- 连接器类型
- key 名称
- 内部服务别名
- 部分脱敏不完整字段

这些信息本身不直接完成攻击，但可以帮助推断：

- 云 key
- 数据库连接器
- 向量库 token
- 内部服务调用路径

### 3.5 工作流导入和插件节点线索

应用渗透智能体还提出两个高影响方向：

1. 工作流导入注入
2. 插件/工具节点执行链

剧本里的关键逻辑是：

- 导入包可携带节点配置、外部 URL、环境变量引用和工具链参数。
- 前端禁用的危险节点，后端仍可能存在解析路径。
- 自定义请求、模板渲染、代码执行类工具节点可以组合利用。
- 可能路径是导入恶意工作流后，触发预览或运行，最终由后端执行器处理。

此时剧本还没有直接进入内网，而是把这些线索交给漏洞分析智能体继续展开。

## 4. 第三阶段：漏洞线索展开

### 4.1 漏洞分析智能体接手

漏洞分析智能体接收 Web 渗透阶段的攻击面模型。

它没有继续重复扫接口，而是把前面发现的线索拆成几个方向：

- 稳定
- 可复现
- 影响大
- 适合 EXP 后端执行
- 能通向内网或后端接管

### 4.2 未知风险线索排列

剧本中呈现的排列是：

```text
稳定性最高：未授权读取和凭据泄露
影响最大：工作流导入注入和节点执行
适合作为内网拓扑探测：SSRF 连接器
```

随后剧本按这个顺序往下推进：

```text
先拿上下文
  -> 定位凭据和执行器
  -> 推进后端接管
  -> 使用 SSRF / 连接器探测内网
```

### 4.3 EXP 后端接力

漏洞分析智能体把下面这组动作交给漏洞利用智能体：

1. 先做未授权枚举。
2. 再做凭据定位。
3. 随后做导入注入并触发节点执行。
4. 最后用 SSRF 连接器做内网探测。
5. 所有 payload 保留回显和失败边界。

这一步把前面的漏洞线索转成了 EXP 后端可以执行的一组任务。

## 5. 第四阶段：EXP 后端验证

### 5.1 漏洞利用智能体接手

漏洞利用智能体接收：

- 爬虫 URL 清单
- API schema
- 权限矩阵
- 危险节点列表
- 连接器列表
- 漏洞线索优先级

它将这些输入转成 EXP 后端任务队列。

### 5.2 未授权枚举验证

EXP 后端批量重放以下接口：

- `/chatflows/apikey/:apikey`
- `/public-chatflows/:id`
- `/flow-config/:id`
- `/chatmessage/:id`

验证点包括：

- Chatflow ID 格式
- 白名单状态
- 用户/租户归属绑定
- 返回字段范围

确认可抽取：

- 节点列表
- 连接器类型
- credentialId
- 变量引用
- 会话文件路径
- 执行器引用

这一步把“可能 IDOR”变成了“可复现接口重放模板”。

### 5.3 导入注入与节点执行验证

随后，EXP 后端进入工作流导入和插件节点执行验证。

剧本描述中，受控工作流运行后触发后端执行器，并获得容器内环境变量和运行上下文。

逻辑含义：

```text
外网 Flowise-like 控制台
  -> 工作流配置/导入/运行
  -> 后端执行器
  -> 容器运行上下文
```

此时攻击链从“读配置”升级为“进入平台后端执行路径”。

### 5.4 SSRF 与连接器探测

URL loader / webhook 被设定为 SSRF 连接器。

剧本中的探测结果是：

- 127.0.0.1 存在响应差异
- 容器网段部分端口超时
- 可作为内网拓扑探测入口

这一步为内网渗透智能体提供了两个输入：

1. 后端执行能力
2. 可探测内网的连接器能力

## 6. 第五阶段：内网拓扑建立

### 6.2 核心资产定位

内网渗透智能体通过：

- 容器挂载信息
- 连接器凭据
- 内部服务关系

定位到演练中的核心控制验证目标。

这一节点对应的是：

```text

```

在剧本结构中，这一步完成了从 AI 平台后端能力到办公网核心资产的跨域跳转。

## 8. 第七阶段：真实内网日志扩展

剧本在 04:24 建立通向办公网核心权限的可验证路径后，继续追加一段更完整的真实内网攻击阶段日志。

这段不是重新开启一条无关链路，而是把“网络可达、凭据可达、横向可达、域控可验证”的过程展开成更细的演练记录，用于 Attack Flow 展示。

### 8.1 智能代理启动

内网渗透智能体启动主程序，加载：

目标网段设定为：



### 8.2 拓扑测绘

拓扑测绘阶段产出：

### 8.3 凭证审计

凭证审计阶段对本地凭证进行分类：

- 明文口令
- NTLM 哈希
- Kerberos 票据

同时筛除：

- 空哈希
- 过期会话

### 8.4 横向验证

这个阶段证明凭证和会话不只是局部有效，而是具备横向扩展价值。

### 8.5 域环境路径选择

剧本进入域环境路径选择与漏洞匹配阶段。

漏洞分析智能体根据域控环境状态，匹配到域控打印服务相关高危漏洞路径。

匹配条件包括：

- 影响版本
- 服务状态
- 权限条件
- DC01 环境吻合度

结论是该路径与 DC01 高度吻合，可进入域控权限验证阶段。

### 8.6 域控漏洞验证

漏洞利用智能体根据漏洞分析智能体给出的路径，生成演练载荷并触发验证流程。

## 11. 阶段衔接叙事

### 11.1 从资产测绘进入 Web 渗透

剧本的第一段从 `target.com` 开始，没有直接进入漏洞验证，而是先让公开资产测绘智能体完成外网入口收敛。

资产测绘智能体通过公开资产记录筛出 `203.0.113.41:443`，并将其识别为 Flowise-like AI workflow console。这个识别结果带出了平台能力：工作流编排、节点执行、凭据托管、工具市场、Webhook 回调和 API key 管理。

应用渗透智能体接收的不是单个 IP，而是一组围绕 Flowise-like 平台能力展开的攻击面。它接着验证 API 权限边界、工作流导入、凭据管理、危险节点、URL loader 和 webhook listener。

这一段的接力关系是：

```text
公开域名
  -> 公网资产入口
  -> Flowise-like 平台识别
  -> 平台能力枚举
  -> Web/API 攻击面验证
```

### 11.2 从 Web 渗透进入漏洞线索展开

应用渗透智能体在 Web/API 层发现多条线索，但没有直接把所有线索交给 EXP 执行。

它先把线索沉淀为攻击面矩阵：

- 白名单接口 IDOR
- Chatflow 越权引用
- credentials 元数据泄露
- 工作流导入注入
- 插件/工具节点执行链
- URL loader / webhook SSRF

漏洞分析智能体接手后，对这些线索继续拆解并排列优先级。剧本里这一段的作用是把前面的攻击面转成后续 EXP 执行顺序。

这一段的接力关系是：

```text
Web/API 线索
  -> 攻击面矩阵
  -> 未知风险线索展开
  -> 稳定性和影响面排序
  -> EXP 验证顺序
```

### 11.3 从漏洞线索进入 EXP 后端验证

漏洞分析智能体输出的不是单个结论，而是一组执行顺序。

漏洞利用智能体按照这个顺序把任务落到 EXP 后端：

```text
未授权枚举
  -> 凭据定位
  -> 工作流导入验证
  -> 节点执行验证
  -> SSRF / 连接器内网探测
```

在剧本中，IDOR 重放先抽取 Chatflow 配置、节点列表、连接器类型、`credentialId`、变量引用、会话文件路径和执行器引用。随后，工作流导入和插件节点执行验证让攻击链进入平台后端执行路径。

这一段完成了从“信息读取”到“后端执行”的升级。

### 11.4 从 EXP 后端进入内网拓扑

EXP 后端验证出平台后端执行路径后，内网渗透智能体开始利用这个能力建立内网视角。

剧本中的内网路径是：

```text
公网 Flowise-like 控制台
  -> 边界反向代理 / WAF
  -> 内网 Flowise-like 控制台
  -> 工作流执行器
  -> Redis / DB / 向量库 / 内部 API
```

URL loader / webhook SSRF 连接器负责提供内网探测入口，连接器凭据负责提供横向访问线索。后端执行器、容器挂载信息和内部服务关系共同组成内网拓扑。

这一段完成了从“平台后端执行能力”到“办公网核心资产定位”的转换。

### 11.5 从内网拓扑进入域控验证

内网渗透智能体定位核心控制验证目标后，先补齐从 Flowise-like 后端到办公网域环境的过渡证据。

剧本中的网络桥接关系是：

```text

  -> 10.0.160.41 运维路由
  -> 办公网 192.168.10.0/24
```

```text

```

这条节点代表核心资产、网络连通性和脱敏运维域账号可达性已经被确认，不代表最终域控最高权限已经完成证明。最终证明在 05:42 的 DC01 最小化验证节点完成。

这一段的接力关系是：

```text
  -> 脱敏运维域账号可达性
```
